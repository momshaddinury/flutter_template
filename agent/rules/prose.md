# Prose

These rules govern docs, comments, commit messages, pull request text, the state files, and replies to the user. They never touch code or technical terms.

1. Prefer short sentences and active voice. Keep longer sentences when splitting them would reduce clarity. Use the tense that matches the facts.
2. Use familiar, precise words. Cut filler such as "just" or "simply" when it adds no meaning.
3. Prefer literal wording to figures of speech, idioms, and metaphors. Write "use" instead of "reach for".
4. Explain unfamiliar technical terms when the reader needs them. Write "for example" instead of "e.g.".
5. One word for one meaning. `Page` is a route's widget. Use the consuming project's domain terms consistently.
6. Second person where natural. Nothing anthropomorphic: the design "shows", it does not "want".
7. No dash asides. No all-caps emphasis. American spelling.
8. Literal UI text and Figma layer names stay exactly as written.

Sources: Orwell's six rules, ASD-STE100, and the Google developer documentation style guide.
